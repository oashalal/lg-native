# Патчи

Скопируйте `patches/_template` в новую папку, измените `patch.json`, добавьте `index.ts`, README и тест на фикстуре. Для `source`/`ast` укажите полный путь файла, точный `anchor`, `expect` и безопасную замену. Сначала найдите стабильный фрагмент в `fixtures/snapshots/<siteVer>/site`, затем проверьте число совпадений.

Тесты и dry-run:

```bash
pnpm test
pnpm build
node tools/dryrun/index.mjs
```

Поле `enabled` перечитывается при следующем запуске. `--safe-mode` отключает все патчи и доступен в пункте трея как индикатор. Патч не должен автоматизировать игровые действия, менять `/api/*` или обходить защиту.

После загрузки JS/CSS отчёт сохраняется в `profiles/<profile-directory>/reports/patches.jsonl`; для существующего профиля `default` сохраняется прежний путь `profiles/default/reports/patches.jsonl`. Его можно открыть из меню трея «Открыть журнал патчей». Отчёты не содержат cookies, OAuth URL или тела ответов. В Chromium DevTools сводка выводится как `[lg-native] patch reports`; тот же массив доступен через `window.LGX.patchReport()`.

Текущие ограничения и план завершения runtime/AST/native-поддержки описаны в [STATUS.md](STATUS.md).

## Runtime-патч

Поместите исполняемый JavaScript в `index.js` рядом с манифестом. Код выполняется в мире страницы после загрузки `/site/app.js`; доступны объект `settings` и `LGX.settings(patchId)`. До выполнения сайта движок создаёт в этом мире `LGX`: `version().siteVer` содержит версию сайта, `hook` меняет исходный объект, `expose(name, value)` обновляет ссылку, `expose(name)` и `get(name)` возвращают последнее значение. При отсутствии внедрённых патчей и в safe mode LGX не создаётся. `requires` поддерживает `global:Имя` и CSS-селекторы, ожидание — до 10 секунд. Используйте `MutationObserver` для элементов, создаваемых позже, и проверяйте идемпотентность. Изменения локального патча подхватываются после перезапуска. `applied` в отчёте означает внедрение, ошибки выполнения видны в консоли. Патчи имеют полномочия страницы: устанавливайте только доверенный код.

Пример: [city-test-window](../patches/city-test-window/README.md). Native-патчи остаются в разработке; подробности в STATUS.md.

## AST-патч и проверка совместимости

AST-патч выбирает объявление `function` по имени и заменяет его тело. Пример цели: `{"file":"/site/app.js","functionName":"render","expect":1,"replacement":"return 42;"}`. Замена содержит только операторы тела, без внешних фигурных скобок. Число совпадений и синтаксис результата проверяются; вложенные совпадения отклоняются. Другие формы функций и произвольные AST-преобразования пока не поддерживаются.

После `pnpm build` команда `node tools/dryrun/index.mjs` проверяет все локальные снапшоты, а необязательные аргументы выбирают версии. Команда `node tools/dryrun/index.mjs --approve 86794a1329` записывает результаты в `compat/matrix.json` только после успешного прогона всех проверяемых патчей и их `test.mjs`. Для каждого source/AST-патча `test.mjs` экспортирует `test({ version, outputs })`, где `outputs` — Map преобразованных файлов; ошибка или отсутствие теста запрещает утверждение. Runtime и CSS отмечаются `skipped`, так как dry-run их не проверяет; `partial: true` указывает на неполноту снапшота. Для source/AST строгий режим требует `ok` в реестре; `strict: false` допускает неизвестную версию с причиной `unverified`. Непустой `siteVersions` дополнительно ограничивает версии вручную. Код завершения отличен от нуля при ошибке преобразования или отсутствии файла.

Журнал ограничен текущим файлом размером около 5 МБ и одной предыдущей копией `patches.jsonl.1`.

## Сетевые runtime-патчи

Добавьте в `patch.json` поле `"network": {"hosts": ["api.example.com"], "timeoutMs": 10000, "maxBytes": 2097152}` и вызывайте `await LGX.net.fetch("https://api.example.com/data", { method: "GET" })`. Результат содержит `status`, `headers` и текстовое `body`. Запросы исполняются в main без cookies игровой сессии; каждый редирект проверяется по списку хостов. HTTPS обязателен, для localhost разрешён HTTP. Передача заголовков Cookie, Authorization, Origin и Referer запрещена; тело запроса ограничено 2 МБ. Серверный токен и safeStorage пока не реализованы.

`$serverUrl` можно указать в hosts, задав `serverUrl` в `profiles/default/config.json` каталога данных Electron; совпадать должен origin, включая порт. У сетевого runtime-патча собственный изолированный мир Chromium и общий DOM страницы. В нём доступны `settings`, `LGX.net.fetch` и `LGX.log`; JavaScript-объекты и функции страницы, `window.LGX` из основного мира и `global:` в `requires` недоступны. Для работы с публичными глобалами сайта используйте отдельный runtime-патч без `network`. Полномочия не выдаются вызовам из страницы. Доверяйте устанавливаемым локальным патчам: изоляция защищает сетевой мост, но они могут изменять DOM.

Верхняя панель показывает число применённых и включённых патчей по последним отчётам профиля активной вкладки. Для обычных runtime-патчей применение означает внедрение кода; сетевые патчи сообщают результат запуска. Настройки патчей общие для всех профилей и применяются перезагрузкой открытых вкладок.

## Настройки патча

Манифест может объявить `settingsSchema`. Поддерживаются типы `boolean`, `string` и `number`; для строки задаётся `maxLength`, для числа — `min` и `max`:

```json
"settingsSchema": {
  "label": { "type": "string", "label": "Подпись", "default": "Тест", "maxLength": 24 },
  "enabledHint": { "type": "boolean", "label": "Показывать подсказку", "default": true }
}
```

Окно настроек строит форму из схемы, проверяет значения в main и хранит их в профиле приложения. После сохранения патчи перечитываются, а игровая страница обновляется. В `index.js` runtime-патча настройки доступны в локальной переменной `settings`. Ключ `script` зарезервирован движком. Пример — `city-test-window`.

## Стили панели и окна настроек

Панель и окно настроек не имеют собственной фиксированной темы. Main получает из игрового `WebContentsView` `data-skin` и вычисленные значения `--bg`, `--surface`, `--surface2`, `--ink`, `--mute`, `--accent`, `--accent-2`, `--focus`, `--line`, `--gu-*`, `--tx`, `--hd` и `--mono`. Они применяются к корню каждого нативного окна. Обновление выполняется при открытии и затем раз в три секунды, поэтому смена канала или skin во время работы отражается автоматически.

При добавлении новых skin не копируйте цвета в `toolbar.html` или `settings.html`: расширяйте список переменных в `readGameTheme()` и `theme.js`. Настройка `data-skin` ограничена безопасным шаблоном имени и используется только как атрибут корня окна.

Electron e2e запускается командой `pnpm test:e2e` (при отсутствии дисплея — `xvfb-run -a pnpm test:e2e`). Он проверяет LGX на локальной странице с изоляцией контекста, без игровой авторизации. Lifecycle API использует `tabs({action, value?, name?})`; допустимые действия согласуются с main (`new-temp`, `new`, `save-current-profile`, `rename-profile`, `delete-profile`, `activate`, `close`), а ответ содержит `{ok, state}`. Автоматическая fixture может проверять только переходы состояния и cleanup в локальном профиле; OAuth/redirect, реальные cookies, localStorage, WS/SSE, восстановление после перезапуска и визуальную доступность остаются непроверенными ручными сценариями.
