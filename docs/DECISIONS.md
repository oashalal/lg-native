# Архитектурные решения

## 2026-11-17 — Единый lifecycle contract toolbar

Toolbar не дублирует выбор профиля отдельным `<select>`. Все операции проходят через ограниченный вызов `tabs({ action, value?, name? })`; действия lifecycle: `new-temp`, `new`, `save-current-profile`, `rename-profile`, `delete-profile`, `activate`, `close`. Ответы имеют форму `{ ok: true, state }`, где state передаёт только безопасные метаданные: `activeTabId`, `activeProfileId`, вкладки (`id`, `profileId`, `name`, `active`, `status`, `error?`) и профили (`id`, `name`, `saved`, `active`, `tabCount`). Toolbar не получает cookies, токены или пути каталогов. Меню не меняет bounds игрового view отдельной IPC-командой: layout/z-order принадлежат main и должны проверяться визуально вручную.

Последствия: тесты могут надёжно проверять переходы registry/state на локальной fixture, но не должны выдавать их за проверку OAuth, реального хранилища Chromium, WS/SSE или перезапуска приложения.

## 2026-11-17 — Профили Chromium и вкладки

Сессия профиля хранится в отдельном каталоге и создаётся через `session.fromPath`; все вкладки одного профиля используют один объект Session и поэтому разделяют cookies, localStorage и IndexedDB. Разные профили получают разные каталоги, кэш и журналы. Реестр хранит непрозрачные идентификаторы и отображаемые имена отдельно от путей, записывается атомарно и не содержит секретов. Существующий `profiles/default` регистрируется без перемещения.

Вкладки представлены отдельными `WebContentsView`, активной остаётся только одна, остальные сохраняются живыми для WS/SSE. Восстанавливаются только вкладки сохранённых профилей с безопасными игровыми URL; временные профили после перезапуска не восстанавливаются и очищаются только по явным маркерам.

## 2026-11-17 — Минимальный мост страницы

Контекст: код сайта получает `window.__lgNative` из preload, поэтому bridge должен оставаться узким и не раскрывать сведения о профиле.

Решение: мост публикуется только в главном кадре `https://legiongame.gg`. `notify` принимает строки до 120 символов для заголовка и 1000 для текста, ограничен пятью вызовами за минуту и повторно проверяется в main. `patchReport` доступен только игровому кадру и удаляет внутреннее поле `path`; IPC отклоняет вызовы из других кадров.

Последствия: сайт получает только методы отчёта, уведомления и открытия разрешённых ссылок; журнал main сохраняет полные данные отдельно.

## 2026-11-17 — Публичность настроек патча

Контекст: настройки патча нужны одновременно окну настроек и коду в мире страницы, но секреты не должны попадать в обработанный `app.js` или изолированный runtime-мир.

Решение: поле `settingsSchema` по умолчанию закрыто. В page world передаются только поля с `public: true` или `visibility: "public"`; `secret: true` всегда имеет приоритет и не передаётся. Проверка выполняется в main перед сериализацией настроек.

Последствия: публичные значения доступны через `LGX.settings(id)`, а секретные значения остаются в main и профиле.

## 2026-11-17 — Заголовки и MIME кэшированных ресурсов

Тела ответов `fetch` уже декодированы, поэтому при создании ответа протокола сохраняются только `content-type`, `cache-control`, `etag` и `last-modified`. Тип версионированного ресурса записывается в метафайл рядом с телом; для старых записей он определяется по расширению. Ответы с ошибками и 304 передаются без изменения.

## 2026-11-16 — Origin для игрового API

Контекст: в HAR приложения POST игрового API получает `403 bad_origin` и не показывает `Origin`; в Firefox успешные POST содержат origin сайта.

Решение: при пересылке небезопасного запроса к игровому API отсутствующий заголовок восстанавливается только если Electron сообщает `initiatorOrigin` игрового сайта. Существующий заголовок и запросы других источников не изменяются. Практическую проверку с авторизованной сессией ещё предстоит выполнить.

## 2026-11-16 — Перехват только HTTP(S) файлов

Контекст: `protocol.handle` должен кэшировать версионированные файлы, но не ломать авторизацию и транспорт.

Решение: корневые и канальные `/api/*`, `/auth/*`, WebSocket и корневые SSE (`/events`, `/sse`) исключены из кэша и патчинга. HTTPS-запросы проходят через обработчик протокола; исключённые запросы пересылаются через `net.request` с сессией Electron. Остальные ответы кэшируются только при наличии `?v=`; JS/CSS проходят через движок патчей.

Последствия: кэшированные JS/CSS повторно пропускаются через движок без сетевого запроса. Пересылка редиректов, cookies и потоковых ответов требует дополнительной проверки; нельзя считать, что OAuth и SSE полностью независимы от перехвата.

## 2026-11-16 — Safe mode на старте

Контекст: патчи должны отключаться одним флагом.

Решение: `--safe-mode` создаёт `PatchEngine` в режиме пропуска; пункт трея отображает состояние. Переключение без перезапуска оставлено для следующего шага, чтобы не менять уже загруженный сайт.

## 2026-11-16 — Сетевой IPC закрыт до привязки идентичности патча

Контекст: сетевой запрос должен проверяться по `network.hosts` конкретного манифеста.

Решение: общий preload IPC пока отвечает `patch-network-unavailable`; нельзя принимать `hosts` от страницы, так как это превратило бы allowlist в самодекларацию.

Последствия: `LGX.net.fetch` имеет интерфейс, но требует контекст патча/токен capability в следующем шаге.

## 2026-11-16 — Локальные runtime-скрипты

Локальный `index.js` проверяется на синтаксис и добавляется к приложению сайта в мире страницы. Это позволяет менять DOM и использовать публичные объекты без доступа к Node или передачи сетевых полномочий. Патчи считаются доверенным локальным кодом; изоляция друг от друга и отчёт об асинхронном результате пока не реализованы. Требования ожидаются до 10 секунд. Для строгих патчей используется ответ `/site/ver`, отдельно от хэша ресурса.

## 2026-11-16 — AST и сухой прогон

AST-преобразование ограничено заменой тела именованного объявления функции по смещениям Acorn. Количество совпадений строго проверяется, результат разбирается повторно; исходное форматирование остального файла сохраняется. Dry-run применяет тот же движок ко всем доступным снапшотам, проверяя совместимость отдельно от утверждённых версий. Ошибка файлового патча отключает его до перезапуска.

## 2026-11-16 — Сетевые полномочия и панель

Runtime-патчи, объявляющие сетевые хосты, исполняются в отдельных изолированных мирах Chromium. Preload выдаёт каждому миру закрытое полномочие; main проверяет отправителя, scope и манифест перед запросом. Это исключает доступ к JS-глобалам страницы из сетевого патча; DOM остаётся общим. Для защиты хостов редиректы проверяются по отдельности. Сайт размещён в WebContentsView под локальной панелью, чтобы панель не перекрывала игровой интерфейс. Native-патчи остаются в разработке.

## 2026-11-16 — Настройки патчей

Поля пользовательских настроек объявляются в `settingsSchema` манифеста и проверяются в main при сохранении. Переопределения хранятся отдельно от манифестов в профиле; после сохранения движок пересоздаётся, а страница перезагружается. Окно настроек использует отдельный изолированный preload и не получает код патчей.

## 2026-11-16 — Синхронизация темы нативных окон

Тулбар и окно настроек живут в отдельных BrowserWindow и не могут наследовать CSS игрового документа напрямую. Main читает разрешённый список CSS-переменных и `data-skin` из игрового WebContentsView, IPC передаёт снимок в оба окна, а общий `theme.js` применяет его к корню. Периодическое обновление выбрано потому, что сайт может менять skin после загрузки канала или перехода между режимами.

## 2026-11-17 — Реестр совместимости

Для каждой версии `compat/matrix.json` хранит результат каждого патча: `ok`, `failed` или `skipped`. Dry-run проверяет source/AST, остальные виды отмечает как не проверенные; при успешном прогоне `--approve` атомарно записывает результаты, сообщая о неполном снапшоте отдельно. Ошибка не утверждает версию. Строгие патчи требуют `ok`; неизвестные версии для нестрогих помечаются `unverified`, а `failed` запрещает применение. Непустой `siteVersions` — дополнительное ручное ограничение. Старые привязки примеров к `13ebcdcfc1` удалены при переходе к реестру.

## 2026-11-17 — LGX в мире страницы

Контекст: `contextBridge` копирует передаваемые значения, поэтому не подходит для хуков и живых ссылок на объекты сайта. Source-патч публикует новое значение `ME` при каждом присваивании.

Решение: движок вставляет `installPageLGX` в начало обработанного `/site/app.js`, если в файл внедрён хотя бы один патч. LGX, хранилище ссылок и хуки живут в мире страницы до выполнения исходного кода сайта; `expose(name, value)` обновляет значение, `expose(name)` и `get(name)` его читают. Версия и настройки передаются при обработке файла; исполняемый текст патчей в настройки не включается. Preload предоставляет отдельный узкий IPC-мост для отчёта и нативных вызовов. Сетевые патчи сохраняют отдельный изолированный мир и свои полномочия.

Последствия: LGX не создаётся без внедрённых в app.js патчей, включая safe mode. Для новой загрузки страницы создаётся новый экземпляр; runtime-эффекты не отменяются автоматически. Проверка в Electron использует тестовую страницу, поэтому поведение с авторизованной игрой остаётся для ручной проверки.

## 2026-11-25 — Фактический контракт составного runtime-патча

Page и network части runtime-патча разделены по execution world. `runtime.pageScript` работает в page world и может видеть DOM и публичные `window.LG*`; `runtime.networkScript` работает в isolated world и получает только заранее объявленный network capability. Legacy `settings.script` и `index.js` сохраняются как fallback для page script.

Network capability принимает только GET. Main проверяет origin/frame/scope/compatibility, host и endpoint allowlist, HTTPS (HTTP только localhost), redirect limit, timeout и размер body. `json` проверяет содержимое как JSON, не полагаясь на content type. Cookies, credentials, authorization и произвольные чувствительные заголовки запрещены. Capability token не передаётся в page world; прямой сетевой IPC из page world не предоставляется. Ранее описанный page-вызов по patch id заменён isolated capability API.

Последствия: сетевой runtime не может использовать игровые cookies или выполнять ответ как код. `runtime.updateMs` пока только поле контракта; автоматическое обновление engine не реализует. Native остаётся предсказуемым skipped до отдельной реализации.

## 2026-11-26 — Явная политика сетевых путей

Контекст: отсутствие списка путей раньше можно было принять за разрешение любого пути на разрешённом хосте. Строка в runtime-источнике неоднозначна, если трактовать её и как код, и как имя файла.

Решение: пустой или отсутствующий `network.endpoints` запрещает запросы; query разрешён только по явной схеме. Каждая цель и каждый redirect проверяются по одной политике. Строка источника всегда является inline-кодом, файл обозначается объектом `{ "file": "..." }` внутри каталога патча. Это заменяет прежнее описание необязательного ограничения путей.

Последствия: старым сетевым манифестам нужно явно перечислить разрешённые пути. Происхождение URL из DOM технически не проверяется; allowlist остаётся границей безопасности. Реализация полного lifecycle и её production e2e должны проверяться отдельно и не следуют из одного наличия манифеста.

## 2026-11-26 — UI и сообщения runtime

DOM-хелперы создаются непосредственно в соответствующем мире, а не передают DOM-узлы через `contextBridge`. Сетевые `json` и `poll` живут в isolated world; через bridge проходят только сериализуемые аргументы и идентификатор отмены. Poll не перекрывает запросы и останавливается при cleanup.

Межмировой канал использует сообщения текущего документа с фильтрацией по ID патча и ограничениями JSON. Это заменяет локальные несвязанные шины в каждом мире, но не даёт ни конфиденциальности, ни аутентичности: код страницы может подделывать сообщения. Сетевая часть обязана независимо валидировать команды. Electron fixture проверяет передачу между мирами, но не заменяет production IPC e2e.
