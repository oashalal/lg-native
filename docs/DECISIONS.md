# Архитектурные решения

## 2026-11-16 — Origin для игрового API

Контекст: в HAR приложения POST игрового API получает `403 bad_origin` и не показывает `Origin`; в Firefox успешные POST содержат origin сайта.

Решение: при пересылке небезопасного запроса к игровому API отсутствующий заголовок восстанавливается только если Electron сообщает `initiatorOrigin` игрового сайта. Существующий заголовок и запросы других источников не изменяются. Практическую проверку с авторизованной сессией ещё предстоит выполнить.

## 2026-11-16 — Перехват только HTTP(S) файлов

Контекст: `protocol.handle` должен кэшировать версионированные файлы, но не ломать авторизацию и транспорт.

Решение: корневые и канальные `/api/*`, `/auth/*`, WebSocket и корневые SSE (`/events`, `/sse`) исключены из кэша и патчинга. HTTPS-запросы проходят через обработчик протокола; исключённые запросы пересылаются через `net.request` с сессией Electron. Остальные ответы кэшируются только при наличии `?v=`; JS/CSS проходят через движок патчей.

Последствия: кэшированные JS/CSS повторно пропускаются через движок без сетевого запроса. Пересылка редиректов, cookies и потоковых ответов требует дополнительной проверки; нельзя считать, что OAuth и SSE полностью независимы от перехвата.

## 2026-11-16 — Safe mode на старте

Контекст: патчи должны отключаться одним флагом.

Решение: `--safe-mode` создаёт `PatchEngine` в режиме пропуска; пункт трея отображает состояние. Переключение без перезапуска оставлено для следующего шага, чтобы не менять уже загруженный сайт.

## 2026-11-16 — Сетевой IPC закрыт до привязки идентичности патча

Контекст: сетевой запрос должен проверяться по `network.hosts` конкретного манифеста.

Решение: общий preload IPC пока отвечает `patch-network-unavailable`; нельзя принимать `hosts` от страницы, так как это превратило бы allowlist в самодекларацию.

Последствия: `LGX.net.fetch` имеет интерфейс, но требует контекст патча/токен capability в следующем шаге.

## 2026-11-16 — Локальные runtime-скрипты

Локальный `index.js` проверяется на синтаксис и добавляется к приложению сайта в мире страницы. Это позволяет менять DOM и использовать публичные объекты без доступа к Node или передачи сетевых полномочий. Патчи считаются доверенным локальным кодом; изоляция друг от друга и отчёт об асинхронном результате пока не реализованы. Требования ожидаются до 10 секунд. Для строгих патчей используется ответ `/site/ver`, отдельно от хэша ресурса.

## 2026-11-16 — AST и сухой прогон

AST-преобразование ограничено заменой тела именованного объявления функции по смещениям Acorn. Количество совпадений строго проверяется, результат разбирается повторно; исходное форматирование остального файла сохраняется. Dry-run применяет тот же движок ко всем доступным снапшотам, проверяя совместимость отдельно от утверждённых версий. Ошибка файлового патча отключает его до перезапуска.

## 2026-11-16 — Сетевые полномочия и панель

Runtime-патчи, объявляющие сетевые хосты, исполняются в отдельных изолированных мирах Chromium. Preload выдаёт каждому миру закрытое полномочие; main проверяет отправителя, scope и манифест перед запросом. Это исключает доступ к JS-глобалам страницы из сетевого патча; DOM остаётся общим. Для защиты хостов редиректы проверяются по отдельности. Сайт размещён в WebContentsView под локальной панелью, чтобы панель не перекрывала игровой интерфейс. Native-патчи остаются в разработке.

## 2026-11-16 — Настройки патчей

Поля пользовательских настроек объявляются в `settingsSchema` манифеста и проверяются в main при сохранении. Переопределения хранятся отдельно от манифестов в профиле; после сохранения движок пересоздаётся, а страница перезагружается. Окно настроек использует отдельный изолированный preload и не получает код патчей.

## 2026-11-16 — Синхронизация темы нативных окон

Тулбар и окно настроек живут в отдельных BrowserWindow и не могут наследовать CSS игрового документа напрямую. Main читает разрешённый список CSS-переменных и `data-skin` из игрового WebContentsView, IPC передаёт снимок в оба окна, а общий `theme.js` применяет его к корню. Периодическое обновление выбрано потому, что сайт может менять skin после загрузки канала или перехода между режимами.
