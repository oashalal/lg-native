# План: безопасный составной runtime и сетевой API

## Цель и решения

- Запускать page- и network-части независимо; поддержать page-only и network-only патчи. Сетевое capability доступно только в isolated world; page world не получает токен или прямой IPC.
- `LGX.net.fetch(target, options)` и `LGX.net.json(target, options)` доступны в isolated world. `target` может быть именованным endpoint или прямым URL. Прямой URL допустим только при разрешённых host и path; query проверяется по схеме в main. Происхождение строки из DOM или окна технически установить нельзя, поэтому гарантировать его запрет нельзя: защита опирается на allowlist.
- Пустой или отсутствующий allowlist путей запрещает запросы. Это намеренное изменение поведения старых сетевых манифестов: сообщить причину и потребовать явного объявления путей.
- Существующие строки `runtime.pageScript` и `runtime.networkScript` означают inline-код; файл задаётся явно объектом `{ "file": "network.js" }`. Для page-части сохранить `index.js` и `settings.script` как fallback, а для сетевой части существующий `settings.networkScript`. Явный источник приоритетнее fallback.
- `LGX.net.poll(target, ms, cb)` задаёт цель и интервал явно. Существующее `runtime.updateMs` остаётся неактивным и вызывает предупреждение; не придумывать автоматическую цель опроса.
- `LGX.channel` передаёт ограниченные JSON-данные, но сообщения из page world считаются недоверенными. Канал не обещает секретности и аутентичности и не должен сам предоставлять произвольное управление сетью.
- Кэш ответов, ETag и dev watcher вне объёма; реализацию не предусматривать как обязательную часть этого плана.

## Порядок реализации

1. **Загрузчик и схемы.** В `src/shared/manifest.ts` и загрузчике `src/main/app.ts` добавить явные файловые источники, не нарушая существующий inline-контракт. Разрешать только файлы внутри каталога патча, включая проверку абсолютных путей, `..` и symlink. Читать и разбирать Acorn обе части в контексте их фактических обёрток; корректно сообщать об отсутствии и синтаксической ошибке части. Не требовать page-файл для network-only патча. Проверить реальные существующие манифесты и покрыть приоритеты источников тестами.
2. **Двухчастный runtime.** Убрать в `src/main/patching/engine.ts` безусловный пропуск page-части при наличии `network.hosts`; запускать каждую объявленную часть в её мире. Если объявлены hosts, но нет network-скрипта, фиксировать `skipped/network-script-missing` для network-части, не скрывая результат page-части. Согласовать проверку совместимости, enabled, safe mode и scope с фактическим документом и профилем: сейчас обработка `app.js` использует глобальный channel и синтетический page. Определить и реализовать независимое применение `requires`: `global:*` только в page world; остальные требования проверять в нужной среде. Учесть отсутствие `/site/app.js` и обе части при отчёте `runtime-host-missing`.
3. **Lifecycle и отчёты.** Ввести идентичность экземпляра патча на документ/вкладку и cleanup на часть. Различать внедрение page-кода и фактический результат его запуска; отдельно отображать состояния page и network и определить их агрегацию для существующего toolbar и публичного отчёта. Отделить события запросов от статуса применения, чтобы временный сетевой сбой не показывал весь патч отключённым. Сохранять безопасные структурированные причины без URL, токенов, заголовков и тел. `PatchEngine.record()` сам по себе не добавляет патч в `disabled`: не смешивать его с `failed-earlier` файловых патчей.
4. **Capability и IPC.** Удалить fallback по `patchId` в `lgx:net-fetch` и `netFetch` из page bridge. Выдавать capability на конкретный патч, основной frame/документ, WebContents и профиль; при каждом вызове повторно проверять владельца, origin, scope, совместимость и включённость. Отзывать при навигации, закрытии вкладки, перезагрузке настроек, отключении и safe mode. Не передавать токены в page world или отчёты.
5. **Отмена.** Передавать через IPC сериализуемый `requestId`, добавить `lgx:net-abort`, в main хранить `AbortController` для владельца и запроса. Отклонять отмену чужого запроса, учитывать уже отменённый signal, гонки отмены и ответа, timeout и повторную отмену; удалять записи в `finally` и отменять активные запросы при отзыве capability. Не передавать `AbortSignal` через IPC.
6. **Политика URL.** В `src/main/net/network-policy.ts` проверять host, path и query на каждом переходе redirect, а не только исходный path. Сохранить GET-only, отсутствие credentials и запрещённых заголовков, HTTPS с существующим исключением loopback, лимиты timeout, размера и redirect. Определить нормализацию URL, допустимые порты и строгое совпадение путей; исключить URL с credentials и неоднозначные варианты кодирования. Каждый redirect должен соответствовать той же политике, что исходный запрос.
7. **Endpoints и API.** Добавить `network.namedEndpoints` как отображение имён на заранее объявленные URL/`$serverUrl`-пути, сохранив существующий массив `network.endpoints` как path allowlist. При вызове по имени разрешать адрес в main; при прямом URL применять тот же allowlist. Добавить явную схему разрешённых query-параметров с типами и лимитами; без схемы query запрещён. Проверять согласованность имени, host, path и конфигурации `$serverUrl` отдельно для каждого профиля. `json` проверяет 2xx и JSON; выдавать стабильные коды `host-not-allowed`, `endpoint-not-allowed`, `invalid-query`, `timeout`, `too-large`, `bad-status:<status>`, `invalid-json`, `aborted` и безопасный общий код сетевого сбоя. HTTP 5xx и timeout регистрировать как warning-события, не отключая патч.
8. **Общие UI-хелперы.** Вынести переиспользуемые DOM-хелперы для обеих сред, учитывая что `installPageLGX` сейчас сериализуется через `toString()` и не может замыкаться на импорты. В isolated world добавить selector-only `ready`, публичные `settings`, `theme`, `mount`, `modal` и попатчевый `onCleanup`. Исправить `modal` (ошибочный CSS и регистрацию cleanup), проверить повторное закрытие, вложенные окна, focus и scroll lock. Строковые HTML-аргументы существующих методов не считать безопасными для внешних данных.
9. **HUD, вывод и канал.** Добавить `LGX.hud.button` с дедупликацией, восстановлением после пересоздания HUD и очисткой observer; предусмотреть клавиатурную доступность. Добавить безопасный `LGX.ui.text` или `jsonView` на текстовых узлах. Реализовать `LGX.channel.send/on` для JSON с ограничением размера, глубины и частоты, изоляцией по патчу и вкладке и отпиской на cleanup. Зафиксировать, что сообщения page world могут быть подделаны; network-скрипт должен самостоятельно валидировать сообщения и не превращать канал в универсальный сетевой прокси.
10. **Polling.** Реализовать `LGX.net.poll` с минимальным интервалом, без перекрытия запросов, с обработкой ошибок и отменой при cleanup/навигации/отключении. Явно определить контракт callback и возвращаемой функции остановки в API и документации.
11. **Диагностика манифеста.** Проверять некорректные hosts со схемой или путём, endpoint вне hosts, неверные query-схемы, отсутствующие источники и отсутствие профильного `serverUrl` для `$serverUrl`. Ошибки отдельных патчей не должны останавливать загрузку остальных и должны быть видны в отчётах, а не только console.
12. **Шаблон и документация.** Создать `patches/_template-network/` с манифестом, файловым isolated-скриптом, кнопкой, окном и безопасным JSON-выводом; показать отдельный составной пример только при необходимости page globals. Обновить `docs/PATCHES.md` и `docs/DECISIONS.md`, явно отметить заменённые архитектурные решения; обновить `docs/STATUS.md` при изменении статуса этапов. Описать изменение старого пустого allowlist, новые сигнатуры, ограничения канала, `updateMs` и реальные гарантии безопасности.

## Проверка

- Unit: разбор манифестов и путей, приоритет источников, обе части и ошибки загрузки, scope/compatibility/safe mode, независимые требования, отчёты и lifecycle, policy каждого redirect, host/path/query/порты, JSON и коды ошибок, cleanup и poll.
- Electron e2e: использовать production-регистрацию IPC и production-запуск isolated runtime, а не пустой bootstrap или дублирующий обработчик. Локальный `127.0.0.1` JSON-сервер проверяет успех, отказ по host/path/query, timeout, большой ответ, redirect на запрещённые host и path, отмену и освобождение ресурсов.
- Негативные e2e: сайт и другой патч не используют чужую capability, нельзя отменить чужой запрос, старый токен не работает после навигации, вкладки и профили изолированы, отключение и safe mode прекращают сетевой доступ; проверить синхронизацию обеих частей и недоверенный канал.
- UI: повторное создание HUD, cleanup observer, modal, focus, scroll lock, недоверенный JSON как текст, смена темы и узкое окно. Ручная проверка живого сайта остаётся отдельной от локального e2e.
- Перед правками выполнить предписанные проектом `pnpm typecheck && pnpm lint && pnpm test`; после каждого связанного этапа повторить соответствующие проверки, затем `pnpm build` и `pnpm test:e2e`. Если среда не позволяет запустить локальный сервер или Electron, явно отметить пропуск, не считать его успешным тестом.
